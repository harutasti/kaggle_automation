# AutoKaggle Project: Deep Analysis & Understanding

## Executive Summary

**AutoKaggle** is an autonomous Kaggle competition system that uses multiple AI agents to iteratively develop, execute, and refine machine learning experiments. The project aims to achieve high scores by leveraging **Codex** (Anthropic's Claude Code CLI) for AI-powered decision making and execution.

**Current State**: Only WAA (Worker AI Agent) uses Codex for experiment execution.

**Goal**: Extend Codex usage to KSE (Knowledge Strategy Engine) and PA (Performance Analyzer) for AI-powered strategy generation and analysis.

---

## 1. Project Architecture Overview

### 1.1 Core Components

```
┌─────────────────────────────────────────────────────────────────┐
│                   MCDU (Master Controller)                       │
│               Orchestrates entire workflow loop                  │
└────────────┬────────────────────────────────────────────────────┘
             │
             ├─────► KIM (Kaggle Interface Manager)
             │       • Downloads competition data
             │       • Crawls discussions using crawl4ai
             │       • Handles submissions (simulated)
             │
             ├─────► KSE (Knowledge Strategy Engine)
             │       • Generates experiment hypotheses
             │       • CURRENT: Programmatic (random strategies)
             │       • TARGET: AI-powered via Codex
             │
             ├─────► EO (Experiment Orchestrator)
             │       • Creates Git worktrees for isolation
             │       • Launches WAA experiments in parallel
             │       • Manages execution lifecycle
             │
             ├─────► WAA (Worker AI Agents) - USES CODEX ✓
             │       • Executes ML experiments
             │       • Trains models, generates predictions
             │       • Currently: Only component using Codex
             │
             ├─────► RAD (Result Aggregator Database)
             │       • Collects experiment results
             │       • Stores scores, logs, artifacts
             │
             └─────► PA (Performance Analyzer)
                     • Analyzes iteration results
                     • CURRENT: Programmatic heuristics
                     • TARGET: AI-powered deep analysis via Codex
```

### 1.2 Data Flow Per Iteration

```
Iteration N:
  1. KSE generates hypotheses (task markdowns)
  2. EO creates worktrees, launches WAAs
  3. WAAs execute experiments using Codex
  4. RAD collects results (scores, logs, artifacts)
  5. PA analyzes results, recommends strategies
  6. Loop back to step 1 with insights

Stop when:
  • Max iterations reached
  • Score threshold achieved
  • No improvement for N iterations
```

## 2. Understanding "Codex" in This Project

**Codex = Anthropic's Claude Code CLI**

- NOT OpenAI's Codex
- It's the `codex` command-line tool from Anthropic
- Executes AI-powered coding tasks autonomously
- Takes markdown task descriptions as input
- Produces code, executes it, generates outputs

**Current Usage**: Only in WAA (via `codex_executor.py` and `codex_launcher.py`)

## 3. Current Implementation Details

### 3.1 WAA with Codex (Already Implemented ✓)

**Files**:
- `src/utils/codex_executor.py` - Core execution engine
- `src/execution/codex_launcher.py` - Integration layer
- `src/execution/eo.py` - Orchestrator that calls launcher

**How it works**:
1. KSE generates task markdown (e.g., `iter0_exp1_task.md`)
2. EO creates Git worktree for isolation
3. EO calls `codex_launcher.launch_experiment()`
4. Codex executor runs: `codex exec --skip-git-repo-check`
5. Codex reads task, executes ML experiment
6. Outputs:
   - `result_{exp_id}.json` - Contains score
   - `DONE_{exp_id}` - Completion signal
   - `submission_{exp_id}.csv` - Predictions
   - `codex_output_{exp_id}.md` - Full output log

**Task Markdown Format** (generated by KSE):
```markdown
# Experiment Task: iter0_exp1_abc123

**Strategy:** LightGBM
**Parameters:** {"learning_rate": 0.05, "n_estimators": 500}

## Instructions for AI Agent (WAA)
1. Load data files: train.csv, test.csv
2. Preprocess data
3. Train LightGBM model with specified parameters
4. Generate predictions
5. Create result_{exp_id}.json with score
6. Create DONE_{exp_id} when complete
```

### 3.2 KSE Without Codex (Current State ✗)

**File**: `src/core/kse.py`

**Current Behavior** (Programmatic):
- Randomly selects from predefined strategies: `["SimpleGBM", "FeatureEngV1_LGBM", "BasicNN", "RandomForest_HyperOpt"]`
- Random parameter generation via `_get_dummy_params()`
- Optionally incorporates crawler discussion insights
- Generates static task markdown template

**Limitations**:
- No deep reasoning about competition characteristics
- No learning from past results beyond simple filtering
- No creative strategy generation
- No analysis of data patterns

**What's Needed**:
- AI-powered strategy generation using Codex
- Deep reasoning over:
  - Competition description
  - Data characteristics (from crawler)
  - Previous iteration results
  - Discussion insights
- Generate multiple creative, well-reasoned hypotheses per iteration

### 3.3 PA Without Codex (Current State ✗)

**File**: `src/analysis/pa.py`

**Current Behavior** (Programmatic):
- Simple statistical analysis: best score, avg, min, max
- Count successes/failures
- Recommend successful strategies for next iteration
- Generate markdown report with heuristic insights

**Limitations**:
- No deep analysis of why experiments succeeded/failed
- No pattern recognition across experiments
- No sophisticated recommendations
- Shallow insights

**What's Needed**:
- AI-powered deep analysis using Codex
- Read all WAA outputs, logs, scores
- Identify patterns, correlations, failure modes
- Generate actionable, detailed recommendations
- Feed insights to KSE for next iteration

## 4. Gap Analysis: What's Missing

### 4.1 KSE Codex Integration Gaps

| Aspect | Current State | Target State |
|--------|---------------|--------------|
| **Idea Generation** | Random selection from list | AI generates creative strategies |
| **Reasoning** | None | Deep analysis of competition + data |
| **Parameter Selection** | Random uniform/randint | Intelligent based on competition type |
| **Past Results** | Simple filtering | Learn from patterns across iterations |
| **Discussion Insights** | Keyword matching | Deep understanding & synthesis |
| **Output Format** | Static template | AI-authored markdown with rationale |
| **Iteration** | No learning loop | Adaptive based on PA feedback |

**Required Work**:
1. Create `KSECodexExecutor` class
2. Build prompt template that includes:
   - Competition description
   - Data characteristics
   - Previous iteration results
   - PA analysis and recommendations
   - Discussion insights from crawler
3. Call Codex to generate N hypothesis markdowns
4. Store AI-generated strategies as "idea markdowns"
5. Wire into MCDU main loop

### 4.2 PA Codex Integration Gaps

| Aspect | Current State | Target State |
|--------|---------------|--------------|
| **Analysis Depth** | Simple statistics | Deep pattern analysis |
| **Failure Analysis** | None | Root cause identification |
| **Feature Importance** | None | Cross-experiment analysis |
| **Recommendations** | Generic | Specific, actionable insights |
| **Learning** | None | Synthesize knowledge across iterations |
| **Output Format** | Template-based MD | AI-authored detailed analysis |

**Required Work**:
1. Create `PACodexExecutor` class
2. Build prompt template that includes:
   - All WAA outputs (logs, scores, errors)
   - Experiment parameters and strategies
   - Competition metrics
   - Historical performance trends
3. Call Codex to generate deep analysis markdown
4. Extract recommendations in structured format
5. Feed back to KSE for next iteration
6. Wire into MCDU main loop

### 4.3 Orchestration Gaps

**MCDU (main loop)**:
- Currently: KSE generates hypotheses programmatically
- Needed: Conditional execution path for KSE Codex mode
- Currently: PA analyzes programmatically
- Needed: Conditional execution path for PA Codex mode

**Configuration**:
- Currently: Only `execution_mode` for WAA ("simulation" or "codex")
- Needed: Separate flags for KSE and PA Codex modes

**Data Flow**:
- Currently: KSE doesn't receive structured PA insights
- Needed: PA outputs structured recommendations consumed by KSE

### 4.4 Logging & Artifact Management

**Current**:
- WAA logs: Plain text or captured in result JSON
- KSE task markdowns: Stored in `experiments/hypotheses/`
- PA analysis: Stored in `experiments/analysis/`

**Needed**:
- Standardized markdown logging for all AI components
- KSE idea library: `experiments/kse_ideas/iter{N}_idea{M}.md`
- PA deep analysis: `experiments/pa_analysis/iter{N}_analysis.md`
- Unified artifact storage structure

### 4.5 Safety & Controls

**Missing Safeguards**:
- No explicit prohibition of Kaggle submissions in WAA tasks
- Submissions should be programmatic only (MCDU decides)
- Need clear separation: WAA = experiment, MCDU = submission

**Required**:
- Update WAA task template to explicitly forbid submissions
- Add validation that submission files are created but not submitted
- Keep programmatic submission logic in MCDU only

## 7. Key Insights & Design Principles

### 7.1 Why This Architecture?

**Git Worktrees**: Each WAA gets isolated workspace
- No conflicts between parallel experiments
- Clean separation of code/data
- Easy cleanup after completion

**Markdown-Centric**:
- Human-readable task descriptions
- AI-friendly format (Codex loves markdown)
- Easy to version control
- Transparent for debugging

**Modular Components**:
- Each component has single responsibility
- Easy to switch modes (simulation vs Codex)
- Testable in isolation

### 7.2 Critical Success Factors

1. **Prompt Quality**: KSE and PA effectiveness depends on prompt design
2. **Feedback Loop**: PA insights must feed back to KSE effectively
3. **Cost Control**: Monitor Codex usage, implement budgets
4. **Safety**: Prevent accidental submissions during experiments
5. **Observability**: Rich logging for debugging and understanding

### 7.3 Challenges & Risks

**Technical**:
- Codex execution time and costs
- Prompt engineering complexity
- Result parsing reliability
- Concurrent execution management

**Design**:
- Balancing automation vs control
- Determining right level of AI autonomy
- Handling AI-generated errors gracefully
